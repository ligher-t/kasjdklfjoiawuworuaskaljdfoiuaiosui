## 3．機械抽出の検査で新たに確定したこと

- **175件／175件**の現行イベント本文オブジェクトを確認。現行ソースには`K(...)`形、`id`が行中にある形、`{"id", "c": [{"l","o"}]}`型の宣言的イベントの複数形式がある。これらを一律の正規表現で「結果枝がない」と判断しない。
- **選択肢488件**を個別索引化。特定イベントの4選択記録と3選択の実コードが不一致。実装する前にカタログ生成器または登録時の合成選択を照合し、生成カタログだけを人手で書き換えない。
- A175件の`after.id`参照として捕捉した全イベントIDについて、全2,566件の既存IDとの参照照合を行い、機械抽出できた範囲の参照先欠落は0。
- `J 36`等の**内部職業番号を物語文へ出す表現**が7イベントで検出された（選択枝では12）。画面上の職業欄は現行IDのまま残し、プレイヤーの物語本文からメタ文字列を除去する方針。
- 全ての候補タグが要修正という意味ではない。例えば負傷から退職を選ぶイベント、療養相談だけのロドスイベント、復職後に短期仕事をするイベントには、既存の本文・効果が整合している枝もある。

主要分類は**維持／発火条件の追加／選択枝の分割／結果因果の修正／後続接続／新世界モデルへ移行／原典保留**。機械的に採用フラグを足すだけで本文との整合を「校閲済み」としない。修正文面は[全般文体基準](../EVENT_PROSE_CAUSALITY_AND_REVIEW_STANDARD.md)に従い、すべて`docs/PLAYER_TEXT_REVIEW.md`で全文比較可能にする。
