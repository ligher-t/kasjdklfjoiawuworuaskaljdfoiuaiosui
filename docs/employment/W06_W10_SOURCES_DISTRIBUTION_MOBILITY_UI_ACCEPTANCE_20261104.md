## W07．地域分布・労働需要・観測値の較正

産業部門の存在率と、特定雇用主の採用可能性は別の分母を持つ。定義は次の通り。

| 指標 | 分子／分母 | 分析単位 |
|---|---|---|
| `p_sector_exists` | 部門が存在する生活圏／事前指定した生活圏×部門 | 固定世界×場所×13部門 |
| `p_site_exists` | 事業所が確定した候補単位／サイト生成候補 | 世界×候補事業所 |
| `p_site_operational` | 開いている実サイト月／実在サイト月 | 事業所×年月 |
| `p_opening` | 募集可能な職位期間／稼働する職位期間 | 職位×期間 |
| `p_discovered` | 実募集を知る人物・応募機会／真に利用可能な人物・応募機会 | 人物×職位×意向期間 |
| `p_reachable` | 到達可能な求人候補／実際に把握した求人候補 | 人物×求人 |
| `p_eligible` | 個別要件を満たす有効候補／審査対象になった有効候補 | 人物×募集 |
| `p_offer` | 内定した有効選考／結果確定した有効選考 | 応募ID |
| `p_started` | 実勤務が始まった内定／承諾済み有効内定 | 雇用episode |
| `p_paid` | 支払済み実働・成果／実際に支払期限を迎えた稼得分 | 人物×期間×支払類型 |
| `p_retained` | 定期時点で継続勤務する採用者／同時点まで追跡可能な採用コホート | 採用コホート |

人口の全人生シミュレーションは不要。実装後、固定少数Seedで19地域の生活圏（移動都市中心／周縁／避難区／固定市街／工業鉱区／小集落／辺境）の存在・募集・経歴の独立した原因を追う。産業存在の高い地域でも就労率は資格・求人・到達・資金・差別・戦乱に制限されうる。正規給与・家業・非現金共同体を同じ失業率に混在させない。サーミ氏族やサルゴンの共同体、カズデル辺境を「貨幣収入0だから無活動」に分類しない。数字は［S］として報告、原作の人口統計・雇用率には転用しない。

**較正停止条件**：もし会社の存在が主人公の職種変更で増える、地域の全住民に同一名前付き企業を紹介する、同じ世界を再訪して会社が変わる、公開されていない求人まで人物が知る、職業J0で経済活動を全く記録できない、という事象があれば実装状態を不合格にする。

## W08．通勤・転居・外勤・歴史的ショック

**交通**：教育P08で定義した往復経路の世界リンクを再利用するが、始業と終業、夜勤、賃金からの実交通費、軍の遠征、外勤の宿泊・付き添い・危険を独立。勤務地`siteId`と住居`homeAreaId`の実交通契約があること、仕事の実在は既存の`MIGRATION_ROUTES`の「地域間移住可能」だけで代替しない。仕事の場所が遠ければ転居相談・寮・遠隔作業・季節赴任・辞退が選べる。会社の採用決定だけで居住地・家族・子の学校を自動移動しない。

**旅**：現行G3の旅行台帳を尊重し、旅立ちから帰還まで`travelPresence`の実不在月を賃金計算へ一度だけ適用。短期の仕事目的の旅と、勤務地移転を別案件で保存。旅先での業務を元勤務先の正式異動・地元企業への新採用に読み替えない。契約の休止／勤務可能性／給与保障は職場ごと。

**歴史**：ロンディニウム等の災厄は現地の稼働サイトと求人にのみ直接、地域内物流には伝播が確認された範囲で間接影響。歴史事象の発生、主人公の現場目撃、後日の伝聞、実際の仕事の消失は四つの記録。イベリアの古い航海職を後世の一般募集へ残さない。シエスタの新旧都市は物理siteが異なるが法人継承や過去の勤務は同一系列で残せる。サーミの越冬・短期間の交易、農繁期など季節性を会社の永久閉鎖として扱わない。

## W09．就職選択UIと本人認知

選択画面の状態を`unaware / heard / verified / screening / offered / awaiting-contract / employed / inactive / closed`に分ける。`workCase`が「ただ応募を考える」時点では職務も給与も確定させない。

| 状態 | プレイヤーに提示できる情報 | 選択と結果 |
|---|---|---|
| 未発見 | 仕事の種類、家族や知人の仕事の噂の範囲。未知企業名・求人枠は隠す | 「地区の仕事口を調べる」「知人に尋ねる」「今は見送る」 |
| 噂だけ | 確かめた発言者・時期・仕事の大まかな種類。条件・合格率は未確定 | 「募集元へ問い合わせる」「移動条件を調べる」 |
| 確認済み | 企業/職位/場所/期間/給与の**確認済み欄だけ** | 「応募」「条件の相談」「見送り」、無効理由の具体表示 |
| 選考中 | 自分が提出した書類・返答期限・把握済み試験結果 | 「結果を待つ」「選考を辞退」 |
| 内定 | 実際のオファー・必要費用・勤務地・契約年月 | 「受ける」「勤務条件を相談」「辞退」、勤務開始前に給与なし |
| 在職・休止 | 実際の契約、実働期間、休日・健康・家族・給与明細 | 「配置の相談」「休職」「退職」「転勤」、当事者の権限内 |
| 離職後 | 前の契約と退職原因、未払・経験・転職支援 | 「再応募」「別の業種を探す」「自営を始める」 |

**無効理由コード**：`work.no-site`、`work.no-opening`、`work.site-closed`、`work.not-discovered`、`work.route-unavailable`、`work.skill-missing`、`work.credential-unverified`、`work.sponsor-required`、`work.language-support-required`、`work.document-missing`、`work.policy-with-source`、`work.under-investigation`、`work.offer-expired`、`work.contract-already-closed`、`work.authority-unconfirmed`、`work.other-party-unconfirmed`、`work.no-available-caregiver`。UIの提示は**本人の知識の範囲**で理由を選び、内部的な理由を全知表示しない。候補ゼロ件でも行動不能にならず、調査・見送り・家業・学習・移動相談などに戻れる。

ユーザーが見る散文の基準は[共通規則](../EVENT_PROSE_CAUSALITY_AND_REVIEW_STANDARD.md)。応募時点で雇用を確定したように表現せず、成功と不採用の結果文を効果と一致させる。既存の文章を変更する際は`PLAYER_TEXT_REVIEW.md`へ全結果を収録。ゲームの職業IDや変数名は物語文面に出さない。

## W10．実装後の最小受入契約

すでに統合仕様に19地域の代表人生R01–R19、横断D01–D20がある。本工程は追加の**課題起点の12件**を固定し、合計51ケースを機能テストの受入母集団にする。以下は**実装前の期待値を定める仕様**。現時点で新実装のテストを実行した報告ではない。

| ID | 入力 | 期待する不変条件 |
|---|---|---|
| X01 | `careerOpeningAssessment({role:"clinical"})`に正しい臨床資格 | 臨床職が常時不適格になる既存条件を解消、研究職の別条件は保つ |
| X02 | `pickStarterJob`が初期職を返すが現地に雇用主ゼロ | 現職IDと給与・勤務地が逆生成されない |
| X03 | J38研究実習→J39→J40と昇進 | 研究部署と内定・実評価・昇進履歴に対応し、直接J40にならない |
| X04 | 社員がいる職場の採用枠はゼロ | 年次給与と在職履歴は残り、新規採用だけ停止 |
| X05 | 家庭内の採掘・鍛冶の手伝い | 無給労働が勝手に正式な年間雇用へ変換されない |
| X06 | 二次資料で確認した企業の商品を海外で買う | 買った地に工場・雇用主を生成しない |
| X07 | 会社の求人を親が知り、子は知らない | 求人情報が本人の知識へ自動伝播しない |
| X08 | 旧会社で鉱石病診断を申告後、新会社に応募 | 旧職場の認知を新会社の確知にしない |
| X09 | 業務旅中の未成年同居子・見守り不同意 | 勤務出張と家族の留守番を自動承認しない |
| X10 | 競技場の短期イベント運営が終了 | 来年の年間給与と職場を残さず、過去職歴は保存 |
| X11 | 退職・失業・再採用を同一年度で繰り返す | 個別`episodeId`と賃金対象月・人生目標の因果を維持 |
| X12 | 同一Seedの再訪・セーブ復元・別人物の求職 | 固定の事業所・募集・採用枠・企業の閉鎖が一意で再抽選されない |

**静的検査**：247地域部門セル、83職業ID、66雇用主体、A175イベントと全488抽出選択枝の一意性・参照対応。  
**実装後に必要な実行検査**：個別職位の採用実績、出入金、家族の所得、元職場の認知、学歴、旅行、軍と強制労働の理由コード、UIでの無効選択、保留から復帰。既存の実装済み教育・旅・感染の回帰が通ったというだけで新雇用システム合格としない。長期人口全周回や大規模な無差別検査は行わず、原因を絞った固定Seedで確認する。
