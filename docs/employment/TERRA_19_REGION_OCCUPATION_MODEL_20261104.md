## 0. 最も重要な結論

学校の設計と同様、求人・仕事の実在を出生・家計・賃金・雇用契約から独立させる必要がある。現行コードは`js/work/contracts.js`で職場ごとの給与倍率・労働時間・募集余地を持ち、42の地域専用職には所属先や退職の履歴がある。一方、`js/life/annual/personal-amounts.js`には未経験者の`pickStarterJob`による一般職の先行決定、`js/world/facilities.js`には`s.job>0`から勤務先を追加する経路がある。

したがって次の11種類の概念を分離する。

1. **産業部門の存在可能性**：地域・生活圏にその産業が成立するか。
2. **生計機会の存在**：企業、共同体、自営可能な需要、公共部門、請負募集などの形態別ID。
3. **当該年月の運営・求人**：勤務先が開き、その役割を募集するか。
4. **本人の認知**：求人掲示、紹介、噂、商会・組織の正式案内を区別。
5. **実地到達性**：居住地区と職務現場の移動、寄宿、長期の外勤。
6. **応募資格**：本人の実取得学歴・専門訓練、技能、言語、経験、法律上の個別資格。
7. **出願・交渉・選考**：申込・推薦・適性試験・面接・結果・期限を案件として保存。
8. **仕事の成立**：採用/請負締結/共同体内役割/自営開始の**異なる確定根拠**。
9. **実際の就業と支払い**：契約年額と実働月数、請負完了、家業・現物受取を区別。
10. **中断・離職・移動**：病気、倒産、天災、徴用、退職、勤務先変更と履歴。
11. **後年の人生**：職歴、技能、傷病、関係、失業、転職、扶養と社会的な立場。

### 設計上の非対称性

学校は原則として学籍と実在校を結ぶ。仕事では**自営・日雇い・家業・共同体での無償労働・宗教的奉仕・徴用・違法な請負**も存在する。これらを一律の「雇用主が契約したサラリーマン」に変換しない。民間の護衛や傭兵、各国の軍務も契約内容・身分・命令系統・実任務を区別する。

学校配置P04の7つの居住地区を再利用するが、教育の存在率を職業へ直コピーしない。地域により同じ「工業・採掘地域」でも軍需、鉱石、重工の構成が異なる。

| 既存地区型 | 仕事機会の主な変化（設計仮案、存在率への加算） | 留意点 |
|---|---|---|
| 移動都市の居住区 | LOG +0.08、COM +0.12、CIV/MED/EDU +0.08、AGR -0.18 | 住民全員に都市内の全業種を自動保証しない |
| 移動都市の周縁区 | MFG/LOG +0.06、COM -0.08、SCI -0.15、非正規雇用形態の比重増 | 都市から隔絶されていることと求人がないことは別 |
| 移動都市の避難・労働区画 | MFG/REC +0.12、SCI/COM -0.17、安定雇用の比重減 | 復興労働・救済と強制労働を個別判定 |
| 固定都市の街区 | COM/CIV/MED/EDU +0.10、LOG +0.06 | 中央商業区と郊外で格差を残す |
| 工業・採掘地域 | MIN +0.25、MFG +0.22、LOG +0.12、CIV -0.06 | 採掘物・汚染・危険は事業所別。MINが0の国でも一律鉱山生成しない |
| 小規模な定住地 | AGR +0.18、REL +0.10、COM -0.14、SCI -0.25 | 家業・共同体仕事は雇用求人を伴わないことがある |
| 辺境・移動の多い居住地 | AGR/REC +0.15、MIL +0.08、CIV/MED/EDU/SCI -0.18 | 狩猟・採集・護衛・小商い等の実生計を可能にする |

補正値は`clamp(p_base + d_area + d_local_special,0,0.98)`で仮に扱う。**極めて稀な産業でも、実際の原作情報・特定都市の産業施設を確認できた場合は「既知の施設」として別登録する**。一方、地区属性だけで一企業を確実に実在させない。

### 地理IDと地域経済の相関

1. `world.occupationWorld.areas[areaId]`に、地域・地区型・都市・生成時刻を保持。
2. 部門の存在は`keyedRoll(worldSeed,areaId,sectorCode)`相当の安定した抽選で固定する。**画面表示や求職問い合わせでRNGを消費させない**。
3. 交通・資源・施設密度等は地区ごとの共通潜在変数に部分相関を持たせ、同じ企業や求人票を毎年・毎回新規生成しない。
4. 通学路と通勤路は道路・輸送サービスを共有できるが、就労時間、通勤負担、雇用主の安全指示は別条件とする。
5. 製造業の需要があっても、専門研究所の採用、国家の官職、秘密警備などは個別の応募制度で絞る。

### 年代の境界

- **イベリア**：大静謐前の港湾・造船・海運の黄金期と、1038年以後の衰退・沿岸警戒・復興を明示的に別扱い。
- **ロドス**：再編時点が1094年内に未特定であるため、既存`sr_rhodes_*`は1095年以降という実装上の条件を維持。
- **チェルノボーグ**：1096年12月以降の直接被害は当該都市の工場・軍・物流に限定。他ウルサス都市には間接波及として記録。
- **シエスタ**：1097年の火山活動・1097年8月以降の新移動都市接続、1099年前後の旧市街閉鎖・交易転換を一つの平時就職率にまとめない。
- **ロンディニウム**：1098年7月を中心とする直接危機と他ヴィクトリア都市の経済的波及を分離。
- **カズデル**：都市中心部の工業・訓練、内戦期の散発的傭兵仕事、1098年後の帰還・再建を別に記録。
- **クルビア**：トリマウンツ研究所と開拓地では雇用市場が大きく異なる。1099年以降の企業事件の変化を「全国の研究所閉鎖」へ一般化しない。
- **イェラグ**：カランド貿易と近代化・鉄道・観光は地域と段階に依存し、以前の山村で常設の工場や列車乗務員を自動生成しない。

年代の**公式事実、二次要約、ゲーム設定を別台帳で扱う**。既存年表の年月・都市スコープが確認されていない業種は、その年の事業所の生死を確定させない。

## 5. 仕事の契約類型と確定条件

| 型 | 本人に必要な証拠 | 年次給与・生活の扱い | 典型例 |
|---|---|---|---|
| `wage-employment` | 募集中の雇用主・採用決定・勤務開始・同意・賃金規約 | 実働月数に応じる賃金台帳 | 工場、研究所、医療、宿泊、一般事務 |
| `public-appointment` | 募集制度、資格・選任、任命権者、現職所属 | 任期・給与・公的身分を別記録 | 官吏、警察、審問官、公的教員 |
| `organization-service` | 実際の組織所属・任務権限・配置 | 賃金・手当・現物給付の有無を個別 | 軍、BSW、ロドス職員 |
| `seasonal-contract` | 期間限定の雇入れ・作業種・期間・対価 | 季節の実働分だけ支給 | 観光、農繁期、興行の裏方 |
| `gig-piecework` | 実際に引き受けた依頼と完了・報酬 | 仕事ごとの受取額。翌年に常勤賃金を付けない | 運搬、修理、傭兵の単発契約 |
| `self-employment` | 店舗・道具・仕入れ・需要または販路・本人開始意思 | 売上−経費−仕入れ。雇用主は不要 | 露店、小商い、職人、行商 |
| `family-community` | 家業・氏族/共同体での当人の役割 | 現物・共有家計・労働義務。無給を失業としない | 農家、共同体の保守、氏族の仕事 |
| `faith-service` | 所属と担当業務・儀礼・運営主体 | 寄宿・現物・給与・奉仕を分離 | 修道院、神職、祈祷や共同体祭祀 |
| `coerced-assignment` | 拘束/徴用の発生元、当事者、区画、命令関係 | 強制、退職不自由、待遇の差を明記 | 強制鉱山配属、軍による拘束労働 |
| `informal-illicit` | 実際の契約や裏社会との接触・信用・対価 | 危険/法的処遇/搾取を別台帳 | 闇市、密輸の一件ごとの運搬 |

**重要**：上記は支払モードの定義であって、事業形態の善悪や法的な一律免許要件を固定するものではない。治療・家庭・避難の非賃金活動も、生活活動として残す。子・家族に関する就労は本人と同一口座・同一職務IDに合算しない。

## 6. 実装候補となるID・状態・FSM

```text
occupationWorld
  areas[areaId]                 地域・地区・産業密度・年代/危機の証拠
  employers[employerId]         企業/役所/組織/請負斡旋/共同体（固定ID）
  sites[siteId]                 実働拠点・個別年月の稼働・危険・移転
  positions[positionId]         職務/参入型/必要技能/資格/条件/報酬
  openings[openingId]           募集職位/募集期間/枠/公知状況
  disruptions[effectId]         危機・再開・閉鎖・倒産・配属変更の履歴

workCases[caseId]                本人ごとの求人認知・応募・交渉と選考
employmentRecords[episodeId]     実際の雇用/請負/家業・開始/終了/勤務先・職種
workEarnings[transactionId]      対象人物・年度/月・払い主・対価・既払いを記録

```

### 標準応募案件（`workCase`）の遷移

```text
interest → discovered → checked → applied → selected
                                            ├─ accepted → contracted → active
                                            ├─ rejected → closed
                                            ├─ deferred → checked / closed
                                            └─ expired → closed
active → leave / dismissal / suspension / transfer / death
```

`discovered`は募集を知るだけ、`checked`は資格・到達・応募可能性の確認だけ。初回提示で費用・雇用契約・職業IDを生成しない。正規採用なら`accepted`後に契約・配属証拠を確定し、職業IDと`employmentEpisodeId`を同時に発行する。自営・家業・短期請負は同じ`workCase`の「選考」部分を必要に応じて省略し、本人の意思と固有の成立根拠を保存する。

求人件数は小規模ゲーム単位のモデルとし、国民人数の統計へ換算しない。学校と同様、**勤務先の存在、運営、求人、本人の認知、到達、資格、合格、契約、実支給**を異なる母数で観測する。

### 資格と教育の接続

1. `educationRecord.schoolCertificates`等の正式修了証を照会する。入学歴・`k`・`ar`の高得点から医師免許や学位を作らない。
2. 徒弟・工房・実務・職場内訓練は`lifeRecord.skills`・非正規学習に記録し、当該求人が認める経験証拠に限って資格不足を補える。
3. 専門職の敷居は国家一律で確定せず**当該雇用主・時期・職位**へ設定する。既存`careerOpeningAssessment`の本人能力と受入主体の認知条件を再利用する。
4. 感染は本人の診断と、**特定雇用主が何を知っているか**を分ける。診断だけで全地域の応募を遮断しない。職場に有効な個別制度・証拠・確度がある場合だけ適用する。
5. 言語・市民身分・後見人・住居は個別の求人・契約条件で確認し、職業IDに対する国籍・種族の一律禁止へ短絡させない。

|---|---|---|---|

### 既存イベントへの責任境界

実装では`job`効果を直ちに削除するのでなく、出現した結果が「承諾済みの採用・自営の開始・家業担当・職務継続・強制配属・単発報酬」のどれかを判定し、**対応する確定根拠が存在した場合だけ職業・所得を同時に更新**する。文体・選択肢・確率は別の監査が完了するまで維持する。成功した技能活動と、資格の付与を一つの効果にまとめない。

## 10. 未確定項目と次工程

**先に固定すべきもの**：本人が働ける職業の範囲、一般仕事・国家職・組織職・独立業の入口、具体的な勤務先IDと空間・求人、個別資格の階層、実際の支払月の定義、保存・復元時の契約不変条件。

**史料に戻す項目**：全国の賃金水準、正式な国家資格・免許、性別/種族/感染者の応募資格、個別企業の人員・給与・求人統計、地区別の産業拠点数、いつからどの職があり得たか。二次情報しかない部分を`S`の仮定で埋める際は、法令・禁止の断定を避ける。

**最小実装順**：P01既存イベントのA全件意味校閲 → P02職業世界の固定IDと地区相関 → P03求人・主体の分類 → P04市区/年代の存在・運営 → P05求職FSM/資格・通勤 → P06仕事会計と現金・時間 → P07既存A/Bイベント移行 → P08保存/乱数/全20代表シナリオ → P09地域別観測/UI。既存の教育世界・交通・元帳を再利用し、`J`番号、`REG`名、実行イベント本文を勝手に改変しない。
