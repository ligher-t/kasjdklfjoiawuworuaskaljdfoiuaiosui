## 1. 重要な設計裁定

1. **産業がある → 会社がある → 事業所が稼働する → その職位が募集される → 本人が知る → 応募できる → 選ばれる → 働く → 対価を受け取る**。各矢印を独立した記録と判定にする。
2. 国名や`J[id]`から事業所を生やさない。学校P02の教育圏と交差可能な**世界で固定された生活圏ID**に`workAreaId`を対応させる。会社は複数事業所を所有でき、部門のある地区すべてに全企業が出現するわけではない。
3. **学校のように一件の「学籍」で全部を表さない**。勤め先との給与契約、公共任命、家業、自営、氏族の現物分配、宗教奉仕、短期請負、徴用など、根拠と会計が異なる。
4. **画面用の主たる職業`s.job`は1件**。その背後の`employmentEpisode`は履歴保存。兼業・一件限りの仕事は`sideEngagements`へ記録し、`s.job=0`の人物にも実際の単発収入や家事・共同体活動があり得る。
5. **実在した会社を全国に複写しない**。ペンギン急便・ロドス・ライン生命等の本社、艦内、支部、外勤地、委託先、商品販売先を区別。企業名を知っているだけで従業員にはなれない。
6. **感染の事実、雇用主が診断を知ること、個別の不当取扱、正式な制度、本人が通知を受けること**は独立。特定感染者の経験から種族や国民全体の一律就職禁止を導かない。
7. 軍務・公職・秘密組織・宗教的役職には、相応の任命者・推薦・実配属・資格確認を要する。現行の「国に居住して`s.job===0`」だけで特殊機関の募集票を現地で発見しない。
8. **就職と雇用継続の関係**を保存。転居・旅・避難・収容・入院で実働月が減っても、一定の条件下では所属自体は残る。倒産・解雇・自然終了・本人辞退は原因を別保存。
9. **地域モデルの0–3、4/20/55/85%、地区補正はS仮定**。存在率、求人数、就業率、賃金分布、求人選考合格率は異なる指標。企業の設立年月や所在地は史料の範囲で確認。
10. 出典のある固有企業・歴史上の団体と、既存ゲーム中の創作的な固有ラベルを別等級にする。未照合名を使った名前付き採用をモデルの自動生成へ繋がない。

## 3. 存在率と地区・企業の固定生成

### 3.1 区分と値

前版の`AGR MIN MFG LOG COM CIV MIL MED EDU SCI CRE REL REC`の13部門と19×13=247セルを保持。0/1/2/3は標準的な**労働生活圏に当該生計機会が存在する**抽選帯で、初期値はそれぞれ`0.04/0.20/0.55/0.85`。**自営需要・共同体仕事の存在**と**賃金労働の求人存在**は別の下位生成である。

生成は以下の順にする。
1. 同一世界の固定`worldSeed`と`workAreaId`を取得。`regionKey`、`localityKind`、特定都市・鉱区・路線・年代を固定し、名前不明の二つの集落が混ざらない。
2. 史料に根拠のある「都市の研究拠点」「採掘中の鉱区」「港湾」「実営業の会社」の**拠点強制配置**があるときは、出典と年月を記録して先に置く。国全土へ連鎖配置しない。
3. 13部門の`p_sector = clamp(baseTier + localityDelta + specificPlaceDelta, 0, 0.98)`を評価。地理に依存する同一の潜在因子（鉱山・交通・市街地密度）を共有して相関させる。学校P04の校舎存在抽選とは独立。
4. 部門がある地区で、形態`wage/public/service/seasonal/gig/self/family/faith/coerced/illicit`別に成立可能な事業所または生計機会を作る。部門が希少でも、実在する特定の企業・施設が根拠付きならその拠点だけは保持。
5. 企業は`organizationKey → employerId → siteId → positionId`。実際の敷地・支部が確認できない場合は本社以外を生成しない。支部の存在と求人枠は別。
6. 年/月の操業、求人募集期間、採用決定、収益を独立更新。UI問い合わせ、再訪、同年再試行で追加企業を作らない。倒産・休業・再稼働は追記型。
7. 同一世帯の家族、主人公、子、過去の勤務地は同じ`siteId`を参照し、人物の死亡・転居によって会社の存在を変更しない。

### 3.3 企業・公共組織・市場の存在の関係

**法人**（ライン生命）は一社、**事業所**（トリマウンツの研究部署とサーミ調査拠点）は別、**部門**（SCI）は多数、**職位**（実習生／研究員／主任）は別、**募集**（今期1枠）は短命。同じ会社の採用が成立しても他の全職種が自動選択可能にならない。

商業連合会の会員企業を商業連合会から直接給料を受け取る職員に数えず、商品が流通する会社を配送先地域の雇用主に数えず、企業と市の取引を正式な採用契約と混同しない。

### 4.1 生活圏における「仕事がある」の最小基準

たとえばカズデルの辺境に`MFG=2`があっても、「ライン生命の研究員」がそこにいることにならない。その地区で土木補修・鍛冶工房などの**MFG業務**が成立し、かつ現実の引受人・道具・資源を持つなら`J18/19/22`等が候補になる。一方、サーミに`CIV=0`でも外来研究拠点の事務役や交易取扱の書記が**具体の現地サイト**に存在する場合は候補にできる。

カジミエーシュの商業連合会は一組織だが、所属企業は別会社。Mieszkoの工場員（`J2`）、新聞編集者（`J13/21`などの下位職務）、競技騎士（`J63`）、会場員（`J32`）、無冑盟（`J64`）を一つの職位として抽選しない。

### 4.2 例外的に固定してよい場所・組織

原作・二次資料に個別の**実在**が確認された拠点に限り`explicitSite`を登録する。例：トリマウンツに本社を持つライン生命、龍門に本拠のあるペンギン急便、イェラグのカランド貿易関連事業、ドッソレスという都市の治安機関。サイトの座標、地区区分、個別の部署、創業年は出典が示す部分だけで確定する。

「この国で製品を扱っている」「ある人がそこへ所属している」という資料は**就労者の存在証拠**にはなるが、「当該地区の全居住者が応募可能」という証拠にはならない。

### 5.2 判定順（読み取り専用）

`knownWorkOption(s, position, date)`（新規の設計名）は**状態変更・乱数消費・契約発行を一切しない**。返却は`reasonCodes[]`、`knownFacts[]`、`unknownFacts[]`、`canApplyNow`、`canFormNow`。

1. **実在**：`employerId`＋`siteId`＋`positionId`が時代・地域・地区に存在。
2. **運営**：当該年月の事業所が稼働。休止・倒産中なら採用を停止、既存勤務の処遇審査は継続可。
3. **募集**：`openingId`が存在、対象役職・定員・応募窓口・公示期間が合致。自営・家業は募集条件を代替する成立要件で判定。
4. **本人の知識**：掲示を読んだ、紹介者に聞いた、誰かの噂などを記録。未照会の世界事実を全知表示しない。
5. **通勤・任地**：徒歩・交通・寮・赴任期間・軍駐屯・護衛の移動先をP02/P08の路線と接続。往路のみでは毎日の職務を保証しない。
6. **技能・資格**：正式課程`awardId`、実務`skill`、アーツ技能`ar`、識字・言語`language`、経験`employmentEpisode`、公的免許／組織内資格を募集ごとに照合。資格の出典がない制限を「法律」としない。
7. **身分・差別**：`policy`は対象企業・役職・期間・証拠・権限を明記。感染認知は応募先の`employerId/siteId`が受領した事実から。履歴にない感染の内密な共有を作らない。
8. **意思・選抜**：採用面接、技術試験、任命、家業継承、個別請負の受諾。拒否・辞退・欠員消滅・門前払いを異なる結果へ。
9. **成立**：勤務・請負・家業・共同体役割の`episodeId`を一度発効。`s.job`は活動中の主職を表示する派生値。
10. **支払**：実際の勤務期間・完了成果・取引と手当を請求／受領台帳に記録。

不可理由は少なくとも`no-site / site-closed / no-opening / unconfirmed-opening / unknown-to-person / route-unavailable / document-missing / skill-gap / certification-needed / employer-policy-documented / waiting-result / offer-expired / cannot-verify-authority`を区分し、制度上の拒絶を捏造しない。

## 7. 応募・契約・離職の有限状態機械

`workCase`は本人・応募先・期日ごとの**案件**。`employmentEpisode`は実際に始まった**勤務・生計**の記録。複数応募は可能だが、主職の活動開始は一つの決済／所属コミットにまとめる。

`intent → discovered → verified → applied → screening → offered → accepted → contracted → active`  
`applied/screening → rejected / withdrawn / expired / deferred`  
`active → suspended → resumed / terminated`  
`active → transferred / resigned / dismissed / contract-expired / employer-closed / forced-ended / died`

- 応募資格の照会と募集枠は読み取り専用。合否や事業所の営業状態を描画のたび再抽選しない。
- `offer`は採用提案。本人の受諾、必要書類、赴任、勤務開始を経た段階で`active`。辞退しても「採用され働き始めた」履歴にしない。
- 原作にない全国法定試験を自動創造せず、公職・特殊組織では個別募集の根拠に即して選考。
- 退職は契約、勤務先、所属を各々終了。既に修了した実務研修・技能・職歴・人生経験は消さない。
- 旅・病欠・学校通学による`suspended`は`terminated`への自動転換を避け、就労できた月の記録から年次給与を算出。
- 現職停止後も、実在した雇用主の倒産・閉鎖・再開歴は世界に保存され、人物の転居・再訪で復活しない。

## 10. 資格・教育・差別・移動との接続境界

### 10.1 教育P01–P20

- 就職時の`university/vocational/arts`修了は、教育側の**実際の課程・発行機関・授与根拠**を持つ`awardId`から参照。初等・前期中等・後期中等も正式修了と学校外学びを区別。
- 会社の技術実習は`learningPaths`または`onboardingTraining`。大学修了、医師免許、正式な源石アーツ課程修了へ勝手に昇格させない。
- 現役教員（`J12`）は学校P03の`institutionId/offeringId`・実勤務site・開講年月に結び、廃校・遠方転校後も当人の職歴と過去の教員関係を保持。
- 実在しない学校や研修所に就職する教員や「学費のない学生を採る大学」を逆生成しない。
- 未成年者の徒弟・工房・手伝いを`lifeSkill`に保存し、有償雇用・徴用・保護者の許諾・修了資格を個別評価。原作に明示のないテラ共通法定就労年齢を創作しない。
- 職業のための学校選択を本人が希望した事実と、**実際に入学・修了・受験した事実**を独立。出願失敗は職場の不採用とは別の結果。

### 10.2 交通・放浪・家族

- `workAreaId`と`educationAreaId`は、世界の地区の同一参照または安定した相互対応を持つ。往復の通勤可否は同一交通リンクで評価するが、勤務時間・交通費・危険・寮・軍移動・護衛任務は別判定。
- 従業員として海外赴任しても、配偶者・子どもが同時に転居した事実にしない。相手と子の学校・介護・住居は独立。
- 現行G3-4の旅行による旧居住職の不在月按分を生かす。放浪中に無関係な現地企業を雇用主にせず、`journey`の一時滞在・出張と正式転居を区別する。
- 親や家族の家業の仕事は、本人の担当と家計分配の受領を記録。家族の事業と主人公の現職が同じ`J`値でも別`episodeId`。

### 10.3 感染者のアクセス・安全・社会制度

- 現行の`careerOpeningAssessment`を出発点とし、雇用主が実際に知る症状・診断・通院日を本人属性と分離。診断があっても無条件に全国の雇用を禁止しない。
- 採用の拒絶、職場の安全配慮、配置変更、嫌がらせ、疾病による労働力低下、官署の法的身分確認はそれぞれ異なる判定。
- 例：クルビア研究所の採用試験に不合格でも、研究所が鉱石病の確定診断を知っていたことにはならない。イベリアの審問官任用で確認した政策・身元調査を、同じイベリアのパン屋へ伝染させない。
- 収容中の強制作業、ウルサス鉱区の命令、ボリバルの徴兵は、応募の有無・自由に離職できるか・未払報酬を保存。現行の定期給与と単純な加点で再現しない。

## 11. 観測設計：存在・雇用・収入の分母を分離

| 指標 | 分母・意味 |
|---|---|
| `p_sector_exists` | 産業存在が固定された`workAreaId×sector` ／ 対象の地区×部門 |
| `p_site_exists` | 固定された事業所／調査対象のサイト生成候補。名前付きの企業は一社を複数地区に複製しない |
| `p_site_open` | 稼働する`siteId×month` ／ 実在する`siteId×month` |
| `p_opening` | 募集が開いている`positionId×window` ／ 実在稼働職位×期間 |
| `p_known` | 実在募集を正しく知っている人物案件 ／ 募集が利用可能な人物案件 |
| `p_reachable` | 到達できる人物案件 ／ 募集既知の人物案件 |
| `p_qualified` | 募集要件を満たす応募案件 ／ 実際に対象の応募要件を照会した案件 |
| `p_hired` | 採用成立した有効応募 ／ 選考を受けた正式応募 |
| `p_started` | 勤務開始実績のある受諾オファー ／ 受諾済みオファー |
| `p_paid` | 有効支払証憑のある就労期間・成果 ／ 対価請求が発生した就労期間・成果 |
| `p_still_employed` | 生存・観測期間内に契約継続する就業者 ／ 同じ採用コホートの観測対象（脱落・死亡別記） |

**求人採用率**を`p_sector_exists × p_hired`で計算しない。地区、事業所、職位、応募者、人物年で分母が違う。現時点のパラメータの静的妥当性から人口の雇用率・年収を実測したと報告しない。

## 12. 実装時のデータ契約と受入判定

`occupationWorld`は学校`educationWorld`と同じ世界内・セーブ単位に属すが別台帳。最低限のデータ契約は以下。

| 正本 | ID・不変条件 |
|---|---|
| `occupationWorld.areas` | `workAreaId`は人物・訪問順・画面表示から独立。既存`placeId`の訪問連番を恒久的世界サイトIDに転用しない |
| `occupationWorld.organizations` | `organizationKey`は企業・自治体・宗教体・共同体などの同一組織を特定 |
| `occupationWorld.employers/sites` | `employerId / siteId`の一意性、運営開始、所在地、産業、親会社、支部、閉鎖・再開 |
| `occupationWorld.positions/openings` | `positionId / openingId`は役割と募集を分ける。給与係数・資格・募集期間・枠 |
| `workCases[caseId]` | 本人、志望、発見情報、応募ID、選考結果、予定入職日、可否理由 |
| `employmentRecords[episodeId]` | 実開始、雇用形態、配属と収益源、現職・異動・離職・再採用履歴 |
| `workEarnings[transactionId]` | 支払の主体と受取人、対象年月、報酬／現物／経費／未払、財務台帳との一意キー |
| `workKnowledge[personId]` | 掲示・紹介・噂・正式通知と受領先の確度・時期。世界事実を人物知識へ自動転写しない |

同一年・同イベント枝・同一応募IDを再実行しても、雇用主、履歴、賃金、転居費用、技能、就職目標を二重に作らない。ゲーム保存は循環オブジェクトを含まない。
