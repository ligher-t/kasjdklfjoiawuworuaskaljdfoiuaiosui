# W09 就職・職場・契約の選択UIと情報境界 v1.0

2026-11-04。未実装の表示仕様。既存の人生イベントの短い散文と教育選択UI（教育P16）に整合する。未発見の求人を当人に全知で示さず、知り得る範囲で働き口を探す過程を表現する。

## 1 画面と情報の4層

1. 「暮らしと仕事」: 本人の現職と実際の就業状態、勤務地、給与/現物、主職・一件依頼、勤務履歴、休職の有無。企業名は本人が実際に把握している場合のみ。
2. 「聞いた働き口」: 実際に掲示を見た、店主から聞いた、友人に紹介された求人・案件。申込期限、採用主体、通勤経路、求められる資格を本人が知る範囲で提示。噂だけなら確定した公募として表示しない。
3. 「応募・受諾」: 紹介を頼む、募集条件を確かめる、書類を提出する、選考を受ける、内定を受諾/辞退する、赴任するを別々の操作とする。応募決定で給与や就業履歴を増やさない。
4. 「働き続ける」: 勤務時間、配置転換の相談、休職、転属、退職、契約更新、賃金未払、単発請負の履行。過去の経緯と現契約の識別子を別々に表示。

画面の照会は全てread-only。UIを表示した回数によって新企業、採用枠、病気、噂、選考結果のRNGを進めない。リンク先の契約状態が変わったら既知の求人も終了/失効として表示するが、職場自体の存在を画面から消滅させない。

## 2 応募判定の理由コード

| reasonCode | 内部意味 | 表示上の制約 |
|---|---|---|
| unknown-to-person | 実際の募集をまだ本人が知らない | 非公開名は候補欄に表示しない |
| unverified-opening | 出所不確かな噂 | 確認の方法が実際にある場合のみ照会操作を出す |
| no-site | その地区に職場なし | 近隣にあると断言せず、別の職探しを案内 |
| site-closed | 職場は存在するが休廃業 | 事実を知った日と停止年月を分ける |
| no-opening | 仕事は存在するが募集なし | 同一会社の別部門が採用中とは推測しない |
| route-unavailable | 通勤/赴任経路が合わない | 片道だけで勤務できると判断しない |
| document-missing | 必要書類を所持していない | 実際の募集の要件に限る |
| skill-gap | 役割に必要な技術・経験不足 | 受講先が実在するときだけ提案 |
| certification-needed | 個別募集に明示の資格が不足 | 原作未確認の国民共通免許を捏造しない |
| employer-policy-documented | 実際に募集主体が適用する制限 | 根拠と期間、受領している情報の範囲に限定 |
| waiting-result | 選考・審査中 | 合否予測を確定表示しない |
| offer-expired | 内定の有効期限を過ぎた | 再応募は新workCase |
| unable-to-start | 採用受諾済みだが赴任できない | すでに給与が出た扱いにしない |

説明は同時に複数存在し得る。表示上は明らかな業務障壁を優先しつつ、感染による差別の実事実がある場合は権利侵害の記録と実際の行為を明記。医療診断を相手に知らせていない場合は「会社が感染を理由に拒否」と書かない。

## 3 情報と行為の整合

求人カードは openingId + knownFacts + knownAsOf に紐づける。都市・会社の存在が事実であっても、募集期間・担当部署・給与・待遇は求人に関する実際の証拠を得たときだけ表示。勤務地は siteLocationHistory、応募時点の時間・住所・学校/家族の状況、旅程の利用可能な経路を参照する。

本人の有効な契約はworkEpisodeとsourceCaseを表示し、採用前の事前研修・見学・試用も区別。給与見積は予測、実支給はW05台帳から別欄。未払・控除・現物給付を混ぜない。家族の就業先は本人が知っている範囲で報告を表示し、全世界の職場情報を会話へ自動流入させない。

## 4 イベント文面との接続

「応募する」選択後にいきなり「職員になった」と記述する場合、元イベントに合否分岐があるかを確認し、実際に合格して採用・勤務を開始した結果でのみ確定させる。選択不可説明や確認ダイアログは短く、書類・足・体力・時期・相手の判断など現場の事情を示す。世界設定の説明をイベント本文の地の文へ詰め込まない。全文の提案・改稿があれば別のPLAYER_TEXT_REVIEWに保存する。

## 5 受入 I01〜I10

I01 UI反復で市場/乱数は不変。I02 公開会社名でも知らない求人は伏せる。I03 噂の表示と正式求人を分ける。I04 no-openingとsite-closedは異なる。I05 応募可と採用確定、勤務開始を分離。I06 根拠なき感染・種族一律拒否を出さない。I07 子育て・旅・学校の制約を実際の状態で評価。I08 失効求人は旧履歴から消えない。I09 配偶者の知らない勤務先を確定表示しない。I10 内部のJ番号や数値抽選のパラメータを物語文に出さない。
