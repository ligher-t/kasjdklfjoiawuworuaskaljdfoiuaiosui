## 比較人生と本編の隔離

- 比較計算は `HL=1`。隠れた `born()` と `die()` は本編のログ・終幕・操作DOMを初期化せず、本編の `terra2` 自動保存を削除しない。
- 比較ごとに `resetSimulationStatistics()` で集計を初期化し、`finally` で呼び出し前の集計を復元する。通常プレイでバッチ用の `STAT.op` が未作成でも計算できる。
- 同じ出生年・誕生日から別seedで個別生成する。一人の例外で他の成功を消さず、失敗は明示する。再試行は別の決定的seed群で最大2回。
- 400年の上限で終末が確定しなかった試行を、死亡した比較人物として表示しない。
- `tests/ending-comparison.test.cjs` は実比較計算、本編状態・RNG・保存・画面の保全と、一人だけ失敗するケースを扱う。意図的な失敗ログと検査そのものの失敗を区別する。

## ログ・台帳・警告

- 年別見出しと絞り込みを維持し、追加ログで毎回全履歴を走査しない。年代ジャンプ索引は撤去済み。`ui-log-years.test.cjs` は同年の重複、絞り込み、追加時の見出し移譲を検査する。
- 台帳4分野は既存DOMを移設して利用し、退出時に元のDOM・開閉状態・ページ・ログ・人物欄の閲覧位置を復元する。分野切替の移動先は通常フローの台帳面であり、追従中ナビの画面座標を文書先頭として使わない。
- 台帳は単一の文書スクロール。実在する見出しへのディレクトリ索引と、固定ツールバーの一つの戻る操作・独立した保留復帰を使う。900px未満は索引を初期折り畳み、1280px未満は速度操作を初期折り畳みとする。自動停止と手動速度変更の優先順位は設計契約に従う。

- 指標は現在値と増減を独立した固定列へ分ける。終幕は健康・幸福の指数軸と純資産の龍門幣軸を分離し、実額目盛・0基線・実際の最小最大値・数表を表示する。数表は12時点以下なら全件、それより長い履歴は最初・最後と5記録ごとの値を表示し、表示件数と総件数を区別する。グラフは全記録を使い、等間隔の十進目盛と桁数に応じた余白を確保する。

## 構図と資料・選択の表示境界

- `terra-identity.css` に構図・文字・配色・資料・選択の責務をまとめ、重複した旧上書きや廃止済み危機バナーの装飾を除く。新しいスタイルシートや外部依存は追加しない。基礎のコントロール・モーダル・終幕は既存のCSSを利用する。
- 人物の名前・年齢は `renderPlayerSummary` が既存の公開可能な値から構築する。署名が変わらなければ人物DOMを再構築しない。ログは現在のテキスト・日時・分類・保存形式を維持し、見出しと行間だけを整える。
- 台帳の数値が直前の要約と完全に同文の場合は、同じ値を繰り返さない。独自の金額や指標、診断は既存の公開条件を維持する。数値がなくなった場合は見出し領域を単一列へ戻す。
- `recordTableMarkup` は既存のdt/ddから明示的な未記録値だけを抽出し、表と一つの開閉部へ整理する。家族の「なし」は対象ラベルを限定して別の開閉部へ置き、同居者なし・ゼロ・未診断・安否未確認は本文に残す。生業・家族・地域で同じ表示原則を使い、人生状態とログの保存形式は維持する。
- `setRecordMarkup` は同じ表示内容のDOMを再作成せず、内容が変わる際も `data-record-group` を手掛かりに開閉状態とsummaryのフォーカスを戻す。`organizeLifeRecordSections` は本人向けの表示結果から、未記録の交流・事件資料だけを既存DOMのまま移設する。開示や交流の中身ができれば本文へ戻す。
- 終幕の `lifeSummaryMarkup` は最後に記録された節目と4資料に分ける。生業は通常資料と同じ経歴表示を使い、家族は `lifeSummaryFacts.familyRecords` の関係別の記録を使う。元の一文形式の家族要約もエクスポートに残す。診断前の感染値は本人向け健康要約に出さない。ログ、比較計算、終幕目次のIDは維持する。
- 選択肢は既存の `simulationChoiceStates`・文言・コールバックを利用し、番号と行動を別のspanに分ける。読み上げ名は番号と全文、無効理由は `aria-describedby` で関連付ける。効果や確率から未来の結果を付け足さない。
- スクロールする選択肢の外側は縦flex、各ボタンは縮まないgridとする。短い画面でも折り返した行動文と無効理由が重ならない。`aria-disabled` の透明度を下げず、文字のコントラストを維持する。
- 拡大・狭幅でタイトルをスクロールして開始した場合も、新規人生は画面先頭から読む。無効な出生年で開始を拒否した場合は入力と閲覧位置を維持する。
- 明暗の面・文字色はテーマ指定の詳細度に合わせて再結合する。基礎CSSの古い暗色パレットが勝たないようにする。本文、補足、コントロールの境界、金色主操作はそれぞれの配色でコントラストを確認する。
- シンボルは `terra-identity.css` 内の独自SVGマスク、図版は `assets/ui/` の独自SVG3点。マスク非対応時は文字だけの操作を維持する。装飾SVGは `aria-hidden` とし、ボタンのラベル・選択番号・無効理由を置き換えない。カテゴリの既存 `data-*` 属性を共通の識別に使う。
- `UI_PREFERENCES.motion` は `auto` / `full` / `reduced`。既定 `auto` は `prefers-reduced-motion` に従う。`full` の明示指定で端末演出を有効にし、`reduced` はCSSアニメーション・遷移・滑らかなスクロールを止める。出現はCSSだけで行い、人生の更新や入力受付のタイマーを追加しない。進行ランプの `data-flow` は既存 `sts()` と同じ実状態から設定する。

## 資料ディレクトリと独自図版の接続

- `TERMINAL_RECORDS` は4分野の表示名・分類順・英字・移設元IDの共通定義。現在地は氏名と分野、日付は実際の年・年齢から生成する。疑似的な権限・通信・公的番号を作らない。
- `syncTerminalSectionIndex` は既存見出しのIDを維持し、IDがない見出しに限りUI用の一意なIDを付ける。更新される開閉見出しはネイティブのTab到達性を維持し、既存の資料グループ名から安定したIDを生成し、索引の更新時にも現在項目と操作フォーカスを引き継ぐ。移動時は祖先のdetailsを開き、フォーカスと単一の文書スクロールを合わせる。スクロール追跡は表示中だけrequestAnimationFrameでまとめる。
- 図解は既存の公開射影を再利用する。経歴は仕事・技能・所属と既存の有効な学習年次記録の直近4件まで、関係は本人から見た続柄と既知の状態。年次の学びは全件の開閉欄も置き、空白期間の通学や未表示の態度値は補わない。元の全文と未記録の区分は残す。居住図は構造イメージと明記し、位置や距離をデータとして示さない。
- 表紙・移動都市・固定集落・終幕の独自SVGは `assets/ui/`。寸法を固定してレイアウトを安定させ、画像は装飾として読み上げから除外する。画像未読込でも開始・資料本文・目次を使える。
- 資料入場と分野切替は明示的な閲覧操作でのみ演出クラスを付ける。通常の表示更新では図解・索引の同一内容を再構築せず、入力受付やゲームの更新を演出で待たせない。狭幅の進行操作はネイティブdetailsで開閉する。狭幅の文書スクロールには上下の固定操作を避けるscroll-paddingを持たせ、ネイティブTab移動でも見出しが下部タブに隠れないようにする。
- タイトルの表紙・資料の索引・終幕のファイルを異なる構図と動きにする。通常の応答150ms、資料・選択220ms、表紙600ms、資料束450ms。抑制時には完成形を即表示する。

## 出所・確度と発生条件

- 本人の実際の `s.trace` の選択・日常を根拠に、直近40件を初期折り畳みで閲覧する。
- `EV.conf`・`EV.references` と `SETTING_SOURCES` から資料名・資料種別・安全なHTTPS参照先を示す。欠落は未確認として残す。
- `e.after` に明示された条件を満たし、先行記録が残る場合のみ「発生条件が参照する先行記録」と表示する。条件の前後関係を必然的な因果や人物の意思とみなさない。
- 同年の表示中ログへスクロールとフォーカスを合わせて移動し、成否を操作した資料の直下で通知する。低モーションを上書きする滑らかな移動を指定しない。状態フラグ経由の多段因果はこの機能で一義的に追跡できない。公開可能な理由の追跡を拡張する場合は別の設計判断とする。

## 保守の境界

廃止済みの `density` 設定・適用済み状態変数・台帳退出時の分岐・HTML属性・基本情報を隠すCSSを関連単位で除去した。現行の表示間隔・テーマ・動き・台帳の自動停止は維持する。通常表示の構図・英字分類・独自図版は削らない。旧 `ui-visual-summary` のソース形状の固定検査を除き、公開射影と更新後のフォーカス・5項目の基本情報を検査する `ui-summary-focus` へ整理。旧 `ui-decade-index` は実際の年見出し処理を検査する `ui-log-years` に改めた。高評価の対象を選択入口と既存CIへ登録し、キャッシュは上限64KiBの1ファイルをGit対象外にする。

## 検査の選択

登録と高評価の対象は `../TEST_POLICY.md` と `node tools/check-efficient.cjs list` で確認する。実行は `node tools/check-efficient.cjs run <登録済みの検査ファイル名>`。既存CIが成功した同一入力を理由なく再実行せず、変更・新しい失敗・未解消の懸念に対応する検査だけを選ぶ。文書更新だけではゲーム検査を実行しない。
