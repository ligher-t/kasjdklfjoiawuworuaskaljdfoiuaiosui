## 0. 要旨・資料の読み方

本設計の中心は、**感染成立 → 病勢 → 結晶病巣の分布 → 組織機能障害 → 症状・後遺障害 → 個人の生活・将来**を、相互に関連しながら区別できる状態で保存することである。

感染が確認されても可視病変がなく、重篤な症状がなくても病変が進行しうる。反対に、数値上は軽度でも神経系に顕著な影響を受ける人物がいる。感染者が社会で遭遇する差別は、身体症状と別の出来事・認知・行為に由来する。ゲームでは一つの感染数値から難聴・失職・家族の拒絶を同時に導かない。

証拠区分：

- **P** 原作の日本語プロファイル、ゲーム内の医療記録・本文。閲覧先がゲームテキスト転載サイトの場合は「原作テキストのミラー」と明記する。
- **S** 原作の英語プロファイル・公式訳の再掲。固有名詞とニュアンスは日本語版との照合余地がある。
- **W** 世界設定を二次的に整理したWiki。医療の総論・伝播機序は、引用されている『Terra: A Journey』等の一次出典への遡及を前提とする。
- **H** 本作の世界観解釈・蓋然性に基づく仮説。原作が集団頻度や因果を断定していない領域。
- **G** シミュレーションを成立させるための数値・分岐規則。医学統計・テラ世界の実測値ではない。
- **U** 未確認。実装時は他の証拠へ昇格させない。

個人の病状・医学的因果と、他者の偏見・当局の措置とを混同しない。以下に示す症例は選択バイアスの強い少数のオペレーターであり、人口全体の合併症出現率は不明である。

## 1. 世界観医学の基本契約

### 1.1 鉱石病の基礎

活性源石と生体組織の異常な同化により進行する疾患。皮膚・臓器・神経系などの結晶化、痛みや臓器機能障害、身体的変異が描かれる。発症から死亡までの経過は均一ではない。抑制療法による病勢管理があり、症状の進行速度と身体機能の回復可能性は別に評価する。**通常の時代・医療環境を前提とするゲーム運用では確立した根治を初期選択肢に置かない。** [W:総論]

人物票の「源石融合率（Cell-Originium Assimilation）」と「血液中源石密度（Blood Originium-Crystal Density）」は別の検査値である。両者は時系列で変化し、同程度の数値でも症状が異なる。ゲーム内の `s.ob`（0～100）はそのどちらにもそのまま変換できないモデル上の病勢値である。検査を受けていない人物に「融合率8%」「密度0.43u/L」を自動付与せず、値・検査日・検査施設・結果を知る人物を保存する。

総論の参照先：[Oripathy](https://arknights.wiki.gg/wiki/Oripathy)。そのページは『Terra: A Journey』等に言及する二次資料であり、そこでの「伝播は非常に稀」「血液関連」「不活性化するまでの時間」などの細かい条件は未検証の普遍則として固定しない。出生時感染と単なる親子間接触の因果も分離する。

**適用原則**：`感染した事実`、`感染に至った場面`、`考えられる原因`、`検査で確定した事項`、`本人に知られている情報`、`周囲に広まった噂`を別々に記録する。原因不明の感染を地区の「犯罪」「戦争」「感染者との同居」に自動的に結び付けない。

### 2.1 症例から確実に導ける設計上の制約

1. 体表に結晶がない感染者が存在する。体表所見陰性と感染陰性を同一視しない。
2. 同程度の融合率・血中密度でも症状、社会生活、病勢が異なる。集団の発生確率は症例数から導出しない。
3. 身体上の病巣の位置と臓器の機能障害は一致しない場合がある。全体の病勢と各病変の活動性を分離する。
4. 睡眠障害、難聴、認知障害、運動障害、組織変形のように異なる身体機能の影響を並行保持する。
5. 一部の病態には薬剤・外傷・人体実験・固有アーツなど別原因がある。`causeAttribution` を必須にする。
6. 受療で病勢が安定しても、既に成立した難聴・形態変化等が即座に消えることはない。症状制御と不可逆障害を別状態にする。
7. 原作で特殊な結晶化臓器の機能保持がある。通常抽選に強制せず、物語で明示された極めて稀な状態として扱う。

## 4. 保存する状態の契約

### 4.1 正本と拡張範囲

現在の正本：

- `s.inf`：内部的感染状態。`s.fl.dg`：診断確知。`s.fl.tx`：継続治療。
- `s.ob`：既存の感染負荷（0～100）、`s.ac`：既存の急性進行型フラグ。
- `s.infectionOnset`：`route`、`initialLoad`、`acute`、`affectedArea`、`year`、`basis`。現 `affectedArea` は感染経路に付随する説明用候補部位であり、**実際に画像診断された局所病巣ではない**。
- `s.infection`：本人に関する発症年・診断年、感染経路についての根拠区分。
- `s.oripathyExposure`：曝露時の行為・予防・記録、最大36件の短い履歴。
- `s.mortality.episodes`：現在の `oripathy`、`respiratory` 等を含む全身の医療・死亡危険エピソード。状態を置き換えず接続する。

追加案は `s.oripathyClinical` のみを個別病巣・機能障害・継続ケアの正本とする。旧セーブ修復用の互換実装は不要だが、**新しい保存を同版内で復元した際の再現性**は必要。

### 4.2 データ形の提案

```js
s.oripathyClinical = {
  version: 1,
  initializedYear: s.year,
  lastAnnualYear: null,
  observedMetrics: {
    cellAssimilationPercent: null,
    bloodCrystalDensityUL: null,
    measuredYear: null,
    facilityRef: null,
    observationBasis: null
  },
  lesions: [
    {
      id: "lesion-1",
      site: "auditory-nerve",
      side: "bilateral",
      depth: "internal",
      extent: 1,
      activity: 1,
      visible: false,
      appearedYear: s.year,
      observedYear: null,
      observation: "unobserved",
      cause: "oripathy-probable",
      evidence: "game-model",
      onsetRoute: "unconfirmed"
    }
  ],
  impairments: [
    {
      id: "impairment-1",
      kind: "hearing",
      severity: 1,
      course: "persistent",
      state: "active",

  ],
  carePlan: {
    diseaseSuppression: "none",
    symptomCare: [],
    accessArrangements: [],
    reviewedYear: null
  },

```

設計制約：

- `extent` と `activity` はそれぞれ0～3の段階値。0は現在の活動性または観察を示すため、存在する病巣の履歴を消す目的で使わない。病巣リストの長さ自体を `s.ob` へ合算しない。
- `severity` は0～4（0=症状なし、1=軽い影響、2=日常で調整を要する、3=著しい影響、4=常時支援を要し得る）。職務ごとの要求能力で結果を変える。`residualFloor` は医学的に確立した不可逆性を扱う仮定値で、診断なしに固定しない。
- `observation` は `unobserved / suspected / clinical-confirmed`、`causeAttribution` は `oripathy-supported / multifactorial / unknown / other-confirmed`。**未知・多因子を自動的に感染原因へ昇格させない。**
- 生の観察（本人の訴え・医療記録・第三者の発見）と全知的な内部状態は別。未受診の主人公に血中密度や内部病巣の場所を表示しない。
- `history` に有意な発症・改善・病巣発見・医療相談のみ保存し、年次更新のたびに同じ一行を積み増さない。継続記録の上限は既存の履歴運用に揃える。
- 症状改善で `s.inf` を戻したり、`s.infectionOnset` を更新したりしない。
- 機能評価はまず既存の `s.h` から独立した `functionalCapacity` の導出値とする。二重に体力・収入を減点しない。

### 4.3 最小の列挙コード

病変部位：`skin`、`hand`、`leg-joint`、`auditory-nerve`、`eye`、`upper-airway`、`lung`、`vascular`、`sleep-neural`、`central-neural`、`spinal-neural`、`internal-unspecified`、`racial-organ`。

合併症：`chronic-pain`、`fatigue`、`hearing`、`vision`、`sleep-attack`、`circadian-disorder`、`breathlessness`、`hand-dexterity`、`gait`、`speech`、`memory-attention`、`nerve-pain`、`tissue-deformation`、`arts-dyscontrol`。

状態：`active`、`intermittent`、`stabilized`、`residual`、`resolved`。一つの症状が落ち着いても病巣や他の障害は残る。

### 4.4 多因子性と人物属性

感染源、初期の損傷部位、遺伝的/種族固有の身体構造、年齢、既往の傷害、職場曝露、防護、治療開始時期を独立入力とする。種族名から「必ずナルコレプシー」「必ず難聴」を生成しない。先天性の身体特性は病変とは別。ライフステージの別疾患や戦傷・実験による障害とも症状が重なりうる。

「精神科的・神経学的な変化」には特別な注意が必要。統合失調症等の病名を多くの感染者へ無作為配布せず、原作症例ごとの因果不明や実験的介入を尊重し、一般生成ではまず頭痛・集中困難・睡眠・記憶の一時的支障などの限定的な観測可能症状から扱う。

## 5. 抽選モデル：発症、病巣、症状、後遺障害

### 5.1 既存の感染率は保存する

`js/health/infection.js` の `initializeInfection` を新規感染の唯一の入口として維持する。現行の経路別初期負荷・急性化確率は次の通りで、**すべて既存のゲーム用仮定**である。

| 経路 | `initialLoad` | 急性化抽選 |
|---|---:|---:|
| `dust` | 6～20 | 0.16 |
| `wound` | 14～32 | 0.28 |
| `deep-wound` | 28～50 | 0.48 |
| `mixed` | 12～34 | 0.30 |
| `unconfirmed` | `infection.diagnosisRollMin/Max`、現行値3～12 | `infection.acuteShare` |

この値を源石感染の医学統計として公表しない。未感染の年次推計は `oriAnnualChance`（居住環境・職業・防護・種族のゲーム補正）を引き続き使い、事実として起きた粉塵・刺創と混同しない。`s.inf===1` の場合は再曝露が起きても「再感染」という第二の初回発症を作らない。

### 5.2 病巣の初期配置

発症時に最低0個、典型1～2個の潜在病変候補を内部状態へ作り、検査で実際に発見されるまでは `unobserved`。候補が存在していても必ず症状が生じるわけではない。経路により病変の位置が偏り得るが、全身性病態なので局所に限定されない。

| 曝露経路 | 病巣の配置に使う重みの方向性 | 注意 |
|---|---|---|
| 粉塵 | 肺・上気道を高め、全身にも配分 | 吸入時点で肺が結晶化したという確定描写は禁止 |
| 浅い創傷 | 侵入部位の皮膚・手足を高め、全身にも配分 | `affectedArea` はヒント、身体の実際の部位は別途指定が必要 |
| 深い創傷 | 侵入部位、深部組織・関連神経を高める | 同時に既存の外傷 `mortality` エピソードを維持 |
| 複合 | 呼吸器と創部の候補を保持 | 同じ症状の重複インスタンスを作らない |
| 不明 | 体内・体表の混合分布、発症部位の不確実性大 | 職業名から既往の刺傷を創作しない |
| 先天性 | 出生から存在する病変・進行歴の不確実性 | 母の感染・貧困と同義にしない |

種族固有器官や左/右の表記は `site` に加え `side` と `anatomyVariant` を保持。`visible` は衣服・毛・鱗等の外見的遮蔽とは別。医学的に確認されても周囲の全員が認知したとは限らない。

### 5.3 年次進行と合併症の発現ハザード

既存の `s.ob` 年次増分は `js/life/annual/infection.js` に残す。追加モジュールではこの増分後に症状の経過を更新し、**その年の病勢に基づいた新発症**だけを抽選する。年次の処理順は1回に固定する。

症状群ごとのゲーム用初期ハザード（年間抽選の**例示的な初期値**）：

| 新規症状群 | `ob` 0～24 | 25～49 | 50～74 | 75～100 | 補足 |
|---|---:|---:|---:|---:|---|
| 強い疲労・痛みの自覚 | 1.5% | 3% | 7% | 12% | 痛みと疲労は独立抽選可、重複健康減点を抑える |
| 呼吸器症状 | 0.3% | 0.9% | 2.4% | 5% | 肺・上気道病巣で部位倍率 |
| 聴覚・視覚の機能障害 | 0.15% | 0.5% | 1.4% | 3% | 左右・症状種類を独立決定 |
| 睡眠発作・リズム障害 | 0.15% | 0.4% | 0.9% | 1.7% | 突然の睡眠発作はこの群の少数例 |
| 手・歩行の局所機能障害 | 0.15% | 0.4% | 1.2% | 2.7% | 関連病巣があると上がる |
| 記憶・神経系の支障 | 0.1% | 0.3% | 0.8% | 1.7% | 重篤な精神障害の一律発生率ではない |
| 体の形態変異 | 0.04% | 0.12% | 0.3% | 0.65% | 通常の部位異常成長に限定 |
| アーツ制御失調 | 0.1% | 0.3% | 0.7% | 1.4% | 実際のアーツ適性・使用状況を必要条件 |

上記は**人口・原作に根拠のないG仮定**であり、仮設定時の比較・調整にのみ用いる。短命化や障害過多を招く場合はイベント発火回数と生活上の影響を再較正する。病巣と疾患の出現を別乱数で描き、無傷なのに突然「肺への結晶」を確診することを防ぐ。

例示的な式：`newOnsetChance = clamp(baseByLoad * lesionAffinity * individualVariation * exposureFactor * careFactor, 0, categoryCap)`。

- `lesionAffinity`：関連部位がある場合に倍率1.3～2.5、未観察病変でも内部的には影響、別部位なら1.0を下回らせすぎない。
- `individualVariation`：個人ごとに一度保存する0.6～1.5の素因。毎年再抽選して人物像を揺らさない。
- `exposureFactor`：再曝露や危険環境の実記録がある年に増加。単なる高危険職IDだけでは重い傷害を創作しない。
- `careFactor`：継続治療・症状別治療の実施で新規障害のリスクを下げる。既存 `fl.tx` の病勢抑制と重複して大きな減少を生まないよう初期設定1.0を推奨。後年の学術設定で校正。
- `categoryCap`：年ごとの発症率上限のゲーム側パラメータ。具体値は低負荷試験で調整。
- `newOnset` と既存の `active` な同一 `kind` は重複生成せず、悪化・軽快の更新とする。
- 生活イベントで急性悪化した場合は年次の抽選待ちにせず、効果処理時に一回だけ `impairmentOnset` を発行できる契約を用意する。

### 5.4 重症化・治療・回復の分岐

各障害の年間推移は `stable / worsen / improve` の3択を基本とし、治療の有無、病勢、部位別病巣の活動性、過去の障害年数、補助具を反映する。**治療は病勢の抑制、症状の軽減、生活機能の改善という異なる効果を持つ。** `fl.tx` による抑制開始だけで聴覚を0→正常へ戻さない。

- `reversible`：疲労、疼痛、睡眠リズム等。改善後も既往歴を保持。
- `partly-reversible`：難聴、慢性呼吸器障害、神経症状等。本人固有 `residualFloor` 以下には簡単に回復しない。
- `structural-residual`：組織変形・失われた機能等。病勢が安定しても残存する。
- `special-exception`：サンタラ型の機能を保つ結晶化器官など。一般的な高頻度の救済分岐には入れない。
- `uncertain-causality`：鉱石病以外の病気や医療処置に由来すると確認された場合、治療計画・因果記録を適切な別系統に変更する。

悪化と軽快の年次推移は**何も起きなかった年にも記録上の軽微な変動を過剰表示しない**。実際の選択・診察により認識された時に記録・発話・イベントを生成する。

## 6. 活動能力・仕事・教育・交通への接続

### 6.1 能力を単一の「体力低下」へ潰さない

既存の `personalWorkCapacity(s)` は `s.h` の帯で所得補正を行う。新モデルでは `functionalCapacity(s,task)` を必要時に導出する。`s.h` の変動を伴う症状は体力係数に反映済みとして二重計上を防ぐ。

| 症状 | 不利になりやすい作業 | 生活調整・補助の選択 |
|---|---|---|
| 難聴 | 音声指示のみの現場、口頭授業、警報の聞き取り | 筆談・掲示・光警報・補聴器・読唇・確認復唱 |
| 視覚障害 | 細かな図面、危険箇所の目視、夜道 | 眼鏡・照明・拡大道具・作業分担・移動補助 |
| 睡眠発作 | 高所、運転・輸送、火器・動力機械の操作 | 安全業務への配置、勤務時間の見直し、休憩と同伴 |
| 手の障害 | 精密加工、筆記、調理、衣服製作 | 特注道具・補助具・作業分担・専門技能の転換 |
| 歩行障害 | 長距離通学、山岳・採掘・運搬 | 寄宿舎、交通・移動介助、通勤路の変更 |
| 呼吸器障害 | 粉塵を吸う職、長時間運搬・戦場 | 呼吸を保護する環境、短時間勤務、危険工程の変更 |
| 記憶・集中障害 | 長い手順の独力処理、時間管理 | 書面の手順、同行者、予定表、監督と配慮 |
| 慢性疼痛 | 立ち仕事、反復作業 | 休息・治療・作業姿勢の変更 |
| アーツ制御失調 | 訓練・触媒使用・危険作業 | 安全器具、実技訓練、監督付き運用 |

作業に影響するには`現在の仕事・職場・勤務契約・現場危険`を必要条件とし、職業IDのみから勤務中イベントを発火させない。失業の成立には本人と雇用主の選択、法制度や偏見の別要因があり、障害判定から直接自動失職へ接続しない。

### 6.2 進学・移動・家族の時間

- 児童の難聴が明らかになっても読書・筆記・学力を自動減点しない。授業の連絡方法と教育機関の配慮、対応言語を見て学習アクセスを変える。
- 歩行に支障がある場合、既存の教育機関分布・交通費・寄宿・転居モデルへアクセス制約を渡す。既存の進学可否の所得・学籍判定を迂回しない。
- 家族の付き添いは実際の人物・同居・関係・治療費負担の合意を伴う。親族全員を自動的に介護者へしない。
- 症状別医療費は「検査」「抑制療法」「対症療法」「補助具」「通院交通」「介助」に分け、支払主体、保険、地域医療容量、未払い債務を既存家計へ接続する。受診イベントと年間治療費で同じ料金を二重請求しない。
- 受療歴・休業・道具の購入・友人による支援・技能変更は後年も履歴を保つ。補助具や専門家の支援は一つの選択で永久に万能化させない。
- 死亡リスクは `mortalityState` と `death-risk.js` を正本とする。臓器別の障害状態だけで「突然死」を追加して二重抽選しない。増悪が確定した呼吸不全等は既存 `oripathy` / `respiratory` エピソードの重症度へ接続する。

### 6.3 感染知識、露見と差別

病巣の「見た目」は医療所見、衣服等で見えるか、他人が本人だと同定したか、認められた診断結果が漏れたかで変わる。`infectionWorkplaceAction`、感染者認知台帳、`disclosureImpact` の現行の相手・出典・被害を再利用する。

例：袖から見える手首の黒い病変は同僚の疑惑を生みうる。しかし「他人が見た＝感染者と確診」「認識した＝即時退職」「感染者だから同居家族も感染」とはしない。診断を本人のみが知る場合、イベントは本人の治療と秘匿/相談に限定し、友人や学校が根拠なく診断を知った台詞を出さない。

**実装候補ファイル**：`js/health/oripathy-clinical.js`（状態・年次症状・照会API）、`data/health/oripathy-clinical-events.js`（症状を条件とする場面）の最小2ファイルを主軸とする。`index.html` の読み込み順、`ANNUAL_SERVICES` の注入、`data/finalize.js` の登録を現行APIに合わせる。設定値は既存の `SIM_PARAMS` 系へ必要量だけ追加し、研究専用の第二エンジンを作らない。

現行の `s.inf` を削除したり、`s.ob` の既存乱数を臓器別抽選で置換したりしない。結果の意味が変わる既存イベントはその出典・本文と一緒に改修する。

## 8. 新規イベント草案と後続接続

以下は**未実装の校閲用草案**。既存のイベント文面に合わせ、観察できる事象を具体的に書き、結果を一律に幸福・人脈の増減へまとめない。効果キーは意味上の契約案であり、現行エンジンに登録済みの命令ではない。

### ORI-C01　同じ言葉を聞き返す（難聴の初期認知）

条件：本人に `hearing` 1以上、診断済み/未診断は問わない、在職か学校在籍の実記録、同じ症状段階では一回。聞き取り難を本人が認識している。  
本文案：「朝の引き継ぎで、隣の席から名前を呼ばれたらしい。顔を上げた頃には話が先へ進んでいた。何を頼まれたのか訊き直すと、相手は今度は紙を寄こしてくれた。」  
選択：もう一度説明を頼む／書き残してもらう／診療を相談する。  
後続：書面指示なら現場での行き違いを軽減。診療なら聴覚検査や補助具の選択へ。本人が無断で仕事を辞めた扱いにしない。

### ORI-C02　時間が抜け落ちた（睡眠発作）

条件：`sleep-attack` 1以上、実際に安全性へ影響する職務に就く場合は安全レビュー、日常場面では低危険の描写を選ぶ。  
本文案：「机に置いたペンが床に落ちていた。さっきまで書いていたはずの数字は途中で途切れ、窓の外の光だけが少し変わっていた。何分ほど眠っていたのか、時計を見てもすぐには分からなかった。」  
選択：記録を残す／作業の分担を頼む／医師に相談する。  
後続：発作の記録、診療、危険作業の配置見直し。怠慢として懲罰する場合は実在する雇用主の対応を独立結果へ。

### ORI-C03　粉塵の帰り道（呼吸器症状）

条件：`breathlessness` 1以上、長く歩いた記録や実作業、症状の重症度で文面を変える。  
本文案：「坂の途中で足が止まった。胸の奥が重く、荷物を下ろして息を整える。先を歩く人影が角を曲がっても、すぐには追いかけられなかった。」  
選択：休みながら進む／移動手段を探す／受診する。  
後続：実際の距離、交通利用可能性、支払者、医療容量へ接続。

### ORI-C04　指に合わなくなった道具（手・関節）

条件：`hand-dexterity` 2以上、現在の実職務に手作業が含まれる。  
本文案：「使い慣れた柄が手の中で落ち着かない。握り直すたび、指の付け根に硬いものが当たった。手を休めれば作業は進まないが、無理に力を込めても仕上がりが乱れる。」  
選択：道具を加工する／作業を分けてもらう／診察を受ける。  
後続：補助具費、技能の維持、労働契約・勤務時間との整合。収入を無条件に喪失させない。

### ORI-C05　病巣は写っていた（体内病変の発見）

条件：`internal-unspecified` を含む未観測病巣、実診察行動の結果。  
本文案：「検査の画像には、小さな影が幾つか並んでいた。医師は以前の記録を取り出し、次の検査の日を指で示した。袖口の下に、目立つ結晶はまだない。」  
選択：継続観察の予約／費用と治療の相談／別の医師に意見を求める。  
後続：`observation=clinical-confirmed`、検査済み情報を本人の資料へ、費用は実支払いへ。周囲の診断知識は増やさない。

### ORI-C06　視界がぼける（視覚）

条件：`vision` 1以上、過去の視覚障害未報告。  
本文案：「夕方の帳簿で、細い罫線が二重に見えた。灯りの位置を変えてみても、数字の端がぼやけたままだった。今日の分だけは同僚に読み合わせを頼んだ。」  
選択：照明や道具を調整／診察を予約／読み合わせを頼む。  
後続：診療費、道具、協力関係、実職務での作業負担。

### ORI-C07　検査のたびに少し違う（病勢と症状の乖離）

条件：感染診断確知、治療継続、血中密度の実測二回以上、`hearing` 等の別系統症状が変化。  
本文案：「医師が並べた二枚の記録では、血液の数値に大きな差はなかった。けれどもこのところ、声の聞き取りにくい日が増えている。次の診療では、数値と別に日々の困りごとを伝えることになった。」  
選択：症状日誌をつける／補助具を見直す／仕事と受診日を調整する。  
後続：数値が安定していても合併症の診察へ。**検査値が安定したので聴覚が治癒した**という結果を作らない。

### ORI-C08　病気についての噂（外見と知識の境界）

条件：`visible` な病変、相手が実際に視認した場面、本人が確定診断を開示していない。  
本文案：「配達の帰りに袖が少し捲れた。道端で荷を受け取った男は、手首を一度見てから目を逸らした。釣り銭を数える間、誰も何も言わなかった。」  
選択：そのまま立ち去る／何か言いたいのか尋ねる／手元を隠す。  
後続：相手の疑念と、診断確知、店や近隣での噂の到達範囲を別々に管理。男が感染を確信したと自動設定しない。

### ORI-C09　家族の予定を組み直す（介助と経済）

条件：継続通院が必要、同意した家族関係か公的支援窓口が実在。  
本文案：「診療所の受付で次の通院日を渡された。家の予定を書いた紙と重ねると、家族の仕事の日とぶつかっている。誰に何を頼むか、家へ帰ってから相談することにした。」  
選択：勤務日を変える相談／交通手段を確保／付き添いを頼む。  
後続：実際に承諾した相手だけが介助者となる。家計からの出費と本人の失った就労時間は一度だけ決済。

### ORI-C10　危険作業から持ち場を移す（職場調整）

条件：`sleep-attack`、`vision`、`breathlessness` いずれか2以上、現在の現場が該当危険作業を実施、雇用契約と本人・上司の認知あり。  
本文案：「作業場の監督は帳面を閉じ、今日の工程を指でなぞった。高い足場へ上がる仕事は別の人に任せ、部品の仕分けを続けられないかという。賃金と勤務日数の話は、まだ決まっていない。」  
選択：配置変更を受ける／条件を相談する／診断書の内容を確認する。  
後続：実契約の勤務時間・収入・リスク変更。職業IDだけを上書きしない。

**レアイベント候補（通常抽選から除外）**：特殊実験後の著明な神経症状、機能維持する結晶化器官、アーツ能力の異例な変異は、既存の確定した史料時代・研究環境・人物固有の経験を備えた筋書きに限る。

## 9. 時間経過を通した人生のモデル例

### A　環境曝露→難聴→職場調整→後年の残存障害

- 19歳：火山の野外調査で `dust` に曝露、感染判定。感染経路は現場記録、部位は未診断。
- 20歳：言葉を聞き返す場面が増える。`hearing` 1の疑い、診療は未受診。周囲に診断確知なし。
- 22歳：聴覚検査で機能障害を確認。既存の検査費・通院交通へ課金。専門家の指示に沿って補助具を取得。
- 24歳：`fl.tx` が継続し感染負荷の上昇は減速。しかし `hearing` 2と `residualFloor=1` は残り、口頭指示の職務には書面を活用。
- 34歳：別の大学・職場へ移る。技能・研究経歴は継続し、必要な会話配慮を新しい相手に知らせるかを選ぶ。旧職場の診断知識が自動伝播することはない。

### B　体内神経病変→断続的睡眠発作→安全業務調整

- 25歳：体表に結晶がないまま `sleep-neural` の症状が出る。繰り返す短い睡眠発作を記録。
- 26歳：同僚が居眠りを目撃するが原因は未確知。相談を経て医師が症状を確認し、職務上の危険作業だけ変更。
- 28歳：治療と働き方の調整により大きな事故を避けつつ勤務継続。発作の危険と就業適性は仕事によって違う。
- 32歳：体表病巣が依然見えない。発作が落ち着いても病歴は残り、再増悪時の注意・勤務日程に活用。

### C　深い刺創→局所結晶→生活動線の変更

- 15歳：結晶片が脚に深く刺さり `deep-wound` で感染、外傷エピソードを別途記録。
- 16歳：創傷部の皮膚が硬くなり、長距離の歩行に痛みが出る。通学先は実際の距離と寄宿先の有無で判断。
- 18歳：傷の管理が進み体調は安定。しかし後遺の歩行負担を残し、交通手段と学校選択を本人・家族で見直す。
- 30歳：病勢と離れて変動する古傷の疼痛があり、職種と住環境によって生活への影響が変わる。

### D　先天性感染→呼吸器への影響→技能の継承

- 出生：`congenital` の個別記録があり、母の感染だけで自動設定されたものではない。
- 児童期：採掘地域の源石環境への別の曝露が生じる。出生時の原因を上書きせず、後続環境の影響を履歴へ。
- 少年期：呼吸器症状と通学困難が重なり、地元の作業・家庭での学習、療養の選択肢が変化。
- 成年期：職業変更しても症状・技能・親しい人々の支援は保持。幼少期にあった別原因の発声障害などは感染に誤帰属しない。

上記は**キャラクター再現用の原作時系列ではなくゲーム主人公の仮想例**。確定人物名を本人に割り当てない。

## 10. 医療情報の境界と社会的帰結

内部では、症状や潜在病巣のある人物の状態を持てる。しかし本人が自覚する以前の「肺に結晶が広がっている」といった確定説明をプレイヤーに出さない。身体に見える変化、困りごと、医師による説明は順に異なるイベントとして出す。

- **確知主体**：本人、受診した医師、同意して付き添った家族、手続上知り得た機関、目撃者を実人物・組織に限って保存。
- **知識の種類**：外見の異常、症状の訴え、診断名、詳細な病巣、検査値、就労上の制限を別個に開示。
- **本人の行為**：受診、相談、必要な設備の依頼、秘匿、説明拒否などは同意と事情により結果が異なる。
- **他人の行為**：拒絶・攻撃・受容・援助はその人物・組織の態度、地域、利害に依存し、臓器機能の低下と自動結合しない。
- **特殊機関**：ロドス、ライン生命、地方診療所などは地域・年代・参加資格・現有資金が違う。優れた機関に所属しただけで全員が無料治療・完治となる処理は作らない。

## 11. 検証条件と実装の順序

### 11.1 受け入れ境界

1. 同じ `s.ob` の感染者を生成しても、内部型・表在型・無症状・有症状の組合せが出る。`s.ob` から人物固有の測定融合率・密度を算出しない。
2. `s.inf===0` でも一般の睡眠障害や外傷は存在し得る。その場合の `causeAttribution` は感染にしない。
3. `s.inf===1` かつ `s.fl.dg===0` の検査前表示では体内病変の位置や血中源石値を漏らさない。
4. `dust` と `deep-wound` の初期負荷・急性化・`s.infectionOnset` は既存と同じ契約。病巣抽選追加で乱数系列が変わる箇所は、必要な再現性だけを定義する。
5. 一度の感染イベント・一回の年次処理で病巣を重複生成しない。同年の保存復元と再計算で症状が再発症しない。
6. 医師の確定診断が出ても家族・職場・学校へ自動伝播しない。見える病巣があっても診断情報そのものは保護する。
7. `fl.tx` を1にしたとき感染状態が消えず、残存障害が瞬時に0にならない。症状別治療効果は個別に保持。
8. 病巣の検査値が安定しても、感覚障害が別に悪化し得る。逆に検査値が上昇しても全機能を一様に失わない。
9. 職種が変わった時、難聴・睡眠発作の生活不便度がその業務の要求能力によって変わる。実際の就労契約なしに解雇・配属を変更しない。
10. 家族一人の治療費を本人家計と扶養家計へ二重請求しない。補助具は取得・交換・紛失など記録された事実のみ。
11. 体表病巣なしでも内部感染を持てる。聴覚神経症状と足の病巣が同一位置と誤記されない。
12. `s.h` による既存 `personalWorkCapacity` と症状別の作業機能を二重減算しない。
13. 呼吸器の重症悪化は `mortality` の唯一の死亡候補へ接続し、独立した即死くじを作らない。
14. 原作の固有例（サンタラ型、強制実験型、人格・異常能力の特例）を一般生成の通常分布へ大量投入しない。
15. `observedBy` と情報伝播を人物ごとに持ち、現在の住居・所属が変わった時も過去の療養史・症状履歴は残る。
16. レビュー済みイベントの本文・効果と変更した条件を一致させ、`PLAYER_TEXT_REVIEW.md` にプレイヤー表示全文を登録する。

### 11.2 設計から実装へ移す際の順序

**段階A（状態契約）**：`oripathyClinical` の生成・保存・記録、病巣列挙と症状列挙、潜在/確診境界を実装。新しい大規模イベント追加なし。旧セーブ互換不要。

**段階B（年次と診察）**：年次進行後に症状推移を一回実行し、検査・処置・補助具の明示効果を接続。確定しない症状と因果未判定を許す。`mortality` との二重計上を防ぐ。

**段階C（人生の波及）**：実職場・学籍・地域アクセス・家計・付き添い・履歴へ少数の高影響症状を接続。最初は難聴、睡眠発作、呼吸器、手の障害、歩行負担の5系統。

**段階D（文章・校閲）**：同じ症状が日常に及ぼす影響に連続性を持たせ、発症→検査→調整→後日談を実装。既存の差別モデルから「視認」「噂」「診断」を取り違えるイベントを改稿。新規・変更した表示全文は規定のレビュー台帳へ。

**段階E（調整）**：短期間の状態回帰を行い、症状が毎年表示されすぎないか、所得喪失や死亡が過剰になっていないかを分析。長期大量人数シムを受入条件にしない。

### 11.3 この資料の適用範囲

**実施したこと**：指定ブランチの感染エンジン、年次進行、医療エピソード、死亡判定、人物の診断・治療、家計・学籍・仕事・情報の設計境界を確認し、原作人物の症例を対照して実装案を作成。  
**この文書では実施していないこと**：実際の JS 病巣エンジンと新規イベントの登録、プレイヤー本文の実装、ゲーム内統計値の測定、UIやセーブの動作変更。実装時はその変更に直接関係する高評価の回帰検査を選択する。
