## 集計の読み方

- 自然抽選：通常の出生地域抽選。地域指定時はその地域に固定。
- 地域別同数：人数を地域数（現在19）の倍数にし、地域指定を空にする。各地域への試行割当数を同じにする。中止・失敗時の完了人数まで同じとは限らない。
- 出生居住形態は人数、転居先居住形態は移動回数。同じ人生の複数移動は別件。未知の居住形態を固定集落やゼロ件に置き換えない。
- 人生経路は各イベント処理後・年次更新後の監査を通過した状態で観測する。教育、仕事、配偶者・交際、感染・診断・治療、所属の状態遷移を記録する。順序付き経路は前段を以前の観測点で確認し、後段を初めて観測した人生を一度だけ数える。後段が最初から成立していた場合は数えない。同時成立の順序は推定しない。経路を因果関係とは扱わない。
- 失敗・中止前の観測も集計に含む。完走標本の分布とは母数が異なる。短期試行でゼロでも経路が到達不能とは限らない。
- JSONには lifePaths を追加。同形式の過去レポートにこの項目がなければ未収録と表示する。保存形式・ゲーム状態・乱数処理は変更しない。

### 長時間受入の方法

`tests/fixtures/developer-long-acceptance.html` は明示的な開始操作だけで1000人×最大400年を実行する。1回実行では人生ごとのSHA-256を集約したハッシュと診断レポートのハッシュを出力し、他環境との照合に使う。2回実行では同じブラウザー内で両方を照合する。異なるソース版メタデータで計測した場合は comparisonSource クエリで比較用ソース指紋だけを基準値に正規化でき、実際のソース指紋は出力へ別記する。時刻・所要時間以外の診断情報や人生状態は正規化しない。元の人生・世界・乱数・進行状態の復元も確認し、中止は完走合格と扱わない。通常の自動検査には組み込まない。

Nodeの比較工具には native 引数を追加した。実際の順序付きスクリプトをFunctionの独立したスコープへ読み込み、VM境界の代理オブジェクトの負荷を避ける。別エンジンの複製は持たず、データ・状態・ソースのファイル出力も行わない。VMとnative、Vivaldiの時間は異なる実行環境のため、混ぜて高速化率を算出しない。
