# 全イベント制作・校閲に共通する必須基準

**制定：2026-11-04**／適用範囲：『テラに生まれて』全イベント、教育・仕事・家族・病気・差別・歴史・日常・旅行・老年・各種組織。校閲、新規創作、イベント後続、システム側の文面改稿、表示UI文面に適用。**実装済み本文に自動変更を要求するものではなく、今後の編集時の共通審査契約**。

## 1. 一つのイベントを五つの観点で同時に評価する

1. **設計理念**：架空の一人の人生を、その人が知り得る世界と具体的な生活事情から描く。国家・種族・感染・貧富の差と迫害の過酷さも、穏やかな日常・生計・他者の支援も、資料に照らして表現する。極端な出来事だけでなく、地味な反復・未遂・機会損失を残す。単なる報酬テーブル・全知の歴史解説にならない。
2. **条件・フラグ**：イベントの発火条件、各選択の表示／選択可否、費用・技能・世帯・在籍・契約・健康・感染認知・所在・日時を読み取り、根拠となる正本のIDに対応付ける。真偽フラグは「現在の状態」と「過去の経験」を混同しない。発生しただけで選択結果や後続への承諾を付与しない。
3. **繋がり・因果**：先行イベントの**実際の選択結果**・対象人物・施設・時点を確認する。失敗／辞退／中断／成功は独立。後日談、再発、離脱、再応募、転職、転居、教育・家族・会計への影響まで辿る。必要なフラグの生成／解除／読み手と解除権限を確認。既存イベントとの同義重複を防ぐ。
4. **文面・散文**：現行イベントの生活に根ざした短い散文、視界にある物、身体感覚、労働、地名、関係者、判断の迷いに学ぶ。説明ラベル、表形式の政策解説、機械的な成果宣言を本文に混入させない。格調高さや残酷さを一律化せず、ありふれた生活から政治・病気・差別の衝突へ温度差を作る。
5. **資料と認知**：原作日本語版正式名称を優先。［一次本文］［資料内整理］［二次］［解釈］［ゲーム仮定］［未確認］を分ける。未確認制度・法定資格・時給・企業・学校・路線・年月を正史として確定しない。世界に存在する事実と主人公が知ること、企業・当局・教師が受領した情報を分離する。

## 2. 散文上の具体的な合格条件

- **本文**は場所・状況・生活上の兆候から始める。提示時に未確定の採用・診断・合否・婚姻・勤務先・未来の転帰を先取りしない。誰が言ったか、誰が知っているか、物資はどこから来たかを判断できる。
- **選択肢**は行為または意思とその宛先が明確で、その条件を実際に実行できる。無効条件を採用しつつ、未確定の理由を全知で説明しない。辞退、待機、非正規の代替・自営・共同体といった選択も妥当なら維持する。
- **結果**は**実際に発生した作用だけ**を記述する。調査する→応募する→合格する→契約する→働く→報酬を受け取る、を飛び越えない。結果が失敗なら履歴は失敗、成功なら職歴・現金・所属が実際に変わる。読める結果文と実際の効果が一致する。
- 既存イベントの文体に見られる具体的な事物・環境・人間関係の描写を使いながら、過度な映画的演出、場違いな説教、曖昧な大事件の断言を避ける。必要に応じて過酷で直接的な被害を描きつつ、被害者の情報・主体を省略しない。
- **プレイヤー本文に** `J 36`、`flag`、`eventId`、`＋3`、ゲーム確率・内部資料の等級等のメタ記号を持ち込まない。UI説明・開発者向け注記は本文と別。
- 同一選択に複数結果がある場合、成功／失敗／負傷／拒否／情報のみ取得／金銭授受を個別に照合する。結果だけ確率抽選する実装と、本文が確定結果を描く実装を対応させる。
- 語りの長さは周囲の同種イベントに揃える。指定がない限り、日常は数文、岐路は短い場面＋行動を示す選択＋短い帰結とし、物語の自然な余韻を保つ。

## 3. 校閲の順序と痕跡

1. イベントIDと真の生成元、現行本文、全選択、全結果、条件、効果を読む。`EVENT_CATALOG.md`は生成結果であり正本コードを優先。
2. 設計上の対象人物・生活圏・年月・職位／学校／組織・収入元を確定し、原作史料等級を記録。
3. 先行ID・後続ID、`after.choice/outcome/subject`、`need/ban`、現在フラグの書込／解除、世帯・所属・感染認知への波及を確認。
4. 発生の前提と選択後の実状態に照らし、本文、ラベル、結果のいずれを修正するか、既存のまま保つかを明記。**文章だけ先に差し替えて因果を残さない**。
5. ユーザーが審査できるよう、改稿・新規追加する可視文章を**本文／各選択肢／各結果／条件付き通知の全文**で`docs/PLAYER_TEXT_REVIEW.md`へ記録。ID、出典等級、修正理由、コードの所在と前後のイベントを併記。
6. 実装段階だけ、変更した該当境界を検出する限定テストを選ぶ。新規／変更イベントのカタログは正規生成器から更新する。設計資料のみの工程でゲームテストを実行しない。

## 4. 監査・実装に共通する禁止事項と例外

- 外部の制度情報を抽象的な「全国法」としてすべての人へ適用しない。人物・年代・居住地区・企業・学校・行政主体ごとの根拠を要求。
- 一次物語の一事件を全NPC・全地域の確率として逆算しない。ゲームの数値モデルは［S］と明記。
- 現行フラグや後続を消すことで孤立イベントを「解消済み」にしない。必要なら本当に後続へ線を張り、休止・失効・再挑戦の状態にする。
- 退職や離別が成立しても、過去の面識・修了・職歴・子・負債を黙って消さない。対象人物や世帯、現地施設の正本所有者に沿って処理。
- レビュー時に追加の設定・表現・技術を考案してよいが、実装対象と史料推定の根拠を分け、既存イベントとの重複を一件ずつ調べる。
- 読めない一次史料や日本語で確認できない固有名は「名称照合待ち」として止めるか、資料が許す一般名で表す。過去の翻訳揺れやゲーム中の補完ラベルを正式史実へ昇格しない。
